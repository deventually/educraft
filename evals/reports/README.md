# Eval reports

Generated by the eval runners (see `../README.md`). `npm run eval` writes:

- `<date>.md` — the human-readable per tool × case score table, with a **Δ vs prev**
  column and the weakest-aspect notes.
- `<date>.scores.json` — machine-readable averages, used as the delta source for the
  next run.

Other runners write `<date><label>-<eval>.md`, some with a `…-raw.json` beside it.

**Baseline / after workflow.** Run the harness once *before* editing prompts and
commit that report (the baseline); run it again *after* and commit the delta.

These reports are **generated, never hand-authored** — fabricating scores would
corrupt the only quality instrument the project has.

## What stays here

The folder keeps what is still used; everything else lives in the git history
(`git show <commit>:evals/reports/<file>`). A report stays when

- the repository names it (a tool's `improvedAfter`, a test, a prompt, a decision, the board or
  an eval README);
- its `.scores.json` still holds the latest score of a tool × case, so the next run's
  **Δ vs prev** stays the same;
- it is the latest measurement of its eval.

A `-raw.json` stays only while an eval README still reruns from it (`--from`, `--rescore`).
`tests/evals/reports-folder.test.ts` checks that every named report exists and that every raw file is named.
